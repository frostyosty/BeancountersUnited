An offline, LAN-only tool for a small NZ accounting practice. Staff enter or import client data, keep a
double-entry ledger per client-year, and produce financial statements and fixed asset schedules that
behave like MYOB AO Classic's. One office server owns the data; clients are browsers on the office
network. Nothing talks to the internet at runtime.

**Current milestone: M2.** Before starting work, read that milestone's section in `PLAN.md`.

## What "AO-like" means here (behaviour, not content)
- A practice master chart per entity type; each client's chart starts as a copy of it.
- Account-code ranges map to report lines; a template per entity type lays those lines out.
- Statements show whole dollars with prior-year comparatives, use rounding lines so every column foots, and let any line drill down to its accounts.
- A practice-maintained paragraph library feeds accounting policies and notes.
- An asset register drives depreciation journals and the fixed asset schedule.

## Scope
- In: clients and client-years, charts, journals, TB import, bank statement import and coding (with GST splits for GST-exclusive ledgers), a fixed asset register with user-set accounting depreciation, mappings and templates, statements, finalisation snapshots, PDF output, multi-user on a LAN.
- Out. Don't build these, and don't scaffold them "for later": IRD connectivity; tax calculations (tax depreciation book, IR10, taxable-income reconciliation, RWT/imputation workings); GST returns; payroll; multi-currency; cloud or internet sync; peer-to-peer replication.
- Statements are accounting presentation only. Where the Tax Administration (Financial Statements) Order 2014 applies, its tax items are prepared outside this tool.

## Hard rules
1. No real client data in this repo, its git history, or any Codespace. Fixtures in `fixtures/` are synthetic. Anything that touches real data (M8) runs on an office machine and writes only to gitignored paths.
2. No network access at runtime. That means no CDN scripts, web fonts, telemetry, update checks or external APIs. The UI bundles everything it uses.
3. Don't reproduce MYOB content: template wording, paragraph text, icons or UI assets, and don't transcribe their report templates. Borrow behaviour; write our own content.
4. No floating point for money or rates.
   - Rust: money is `Money(i64)` in cents; rates are `rate_bp: u32` in basis points (12.5% = 1250).
   - TypeScript: money is integer cents, parsed and formatted only through `apps/web/src/lib/money.ts`.
   - The server recomputes and validates everything the UI sends.
5. `crates/core` is pure: no IO, async, clock, randomness or env access. The same inputs always give byte-identical outputs.
6. Every change to practice or client data is a command through the server's pipeline: validate, apply, append to `command_log`, all in one transaction. There are no other write paths: not in handlers, scripts, seeders or fixtures. (Login sessions aren't practice data.)
7. Migrations are append-only. Never edit a committed migration.

## Domain invariants
Each is enforced in core and re-checked in the command pipeline. Each is covered by a unit or property test and by a test that the command is rejected.
- **Journals:** at least 2 lines; lines sum to zero (debit +, credit −); every account exists and is active in that client's chart; the date falls inside the client-year.
- **Immutability:** posted journals never change. Corrections are reversing journals (`reverses_journal_id`). System journals (TB import, depreciation) are regenerated by reversing and reposting inside one command.
- **Books source:** a client-year's books come from TB import or from bank coding, never both, because both would double-count.
- **TB import:** the TB-import journal is the imported TB less the computed opening balances. Re-importing replaces that journal and leaves every other journal alone, so adjustments survive. Re-importing an identical TB posts nothing.
- **Rollover is computed, not posted:** balance-sheet accounts carry forward; P&L accounts close to the client's designated equity account (retained earnings, for a company).
- **Mapping:** every account with a non-zero balance in the current or prior year maps to exactly one report line. Unmapped accounts and overlapping ranges are errors shown to the user, never silently dropped.
- **Rounding:** each line rounds half away from zero to whole dollars. Every column foots, the balance sheet balances, and the P&L profit equals the profit carried into equity. Differences go only to designated rounding lines; which lines those are gets decided in `docs/domain.md` before M1's ReportDoc builder. There is one implementation, in core.
- **Finalised years:** reject any command that would change their numbers. A year can't be finalised before its prior year (if there is one). Only a master user can reopen a year, and must give a reason, which is logged.
- **Snapshots:** finalising stores the TB, the pinned mapping and template versions, the ReportDoc, and a SHA-256 of the ReportDoc JSON. That ReportDoc is the record of what was signed; it is never regenerated.
- **Comparatives:** the prior year's snapshot TB, presented through the current year's mapping and template, so a layout change reclassifies the comparatives too. If the prior year isn't finalised, use its live TB and mark the comparatives as unfinalised.
- **Defaults never reach back:**
  - Practice-level charts, asset classes, templates and mappings are copied, or pinned to a version, at the point where they're used.
  - Changing a default never silently alters existing client data or finalised output.
  - Pushing a change onto existing data is an explicit command. It previews the diff and only touches open years.

## Depreciation (accounting only)
- Methods: `Dv` (rate × book value at the start of the year, or cost in the year of acquisition), `Sl` (rate × (cost − residual), stopping at the residual), `None`.
- Cascade: practice asset class (set by the master user) → client override → a custom rate on the asset itself (staff may set this).
- When an asset is created, the resolved method, rate and conventions are copied onto it, with `rate_source` = `practice | client | custom`.
- Part-year and disposal-year conventions are enums in `acct_core::depreciation`, with defaults set at practice level.
- Compute per asset per year in i128, then round once to cents, half away from zero.

## Architecture (settled; change only with an ADR in `docs/decisions/`)
- **Data ownership:** one office server owns the database; there is no multi-master merge. Clients are browsers until M7 decides otherwise.
- **Server:** Rust, axum and tokio, SQLite via sqlx in WAL mode. One writer connection serialises commands; a read pool serves queries. The server also serves the built web app.
- **SQL:** sqlx runtime queries (`query_as` with `FromRow`), not the `query!` macros, so builds and CI never need a database. Integration tests cover the SQL.
- **Commands:** `POST /api/commands` with `{ id, kind, payload }`.
  - `id` is a v4 UUID from `newId()` in `apps/web/src/lib/id.ts`, built on `crypto.getRandomValues`. `crypto.randomUUID` only exists in secure contexts (HTTPS or localhost), and the office LAN is plain HTTP until M7.
  - `id` is the idempotency key: resubmitting it returns the original result.
  - Accepted commands get an increasing `seq`. Entity ids are server-generated UUIDv7.
- **Reads:** `GET` query endpoints, plus `GET /api/sync?after=<seq>` as the change feed for live refresh.
- **Reports:** core builds a `ReportDoc`: sections, lines, current and prior amounts, styles, and the account codes behind each line.
  - It refers to accounts by code and to lines by template key. It holds no generated ids, timestamps or HashMaps, so its JSON is byte-stable.
  - The HTML preview and the PDF only render a ReportDoc. Golden tests snapshot the ReportDoc JSON, never the PDFs.
- **Shared types:** ts-rs generates TypeScript into `packages/types`; don't edit those files by hand. ts-rs maps i64 to `bigint` by default, but JSON delivers plain numbers, so `.cargo/config.toml` sets `TS_RS_LARGE_INT = "number"` under `[env]`.
- **Roles:**
  - `master`: practice settings, users, defaults, master charts, templates, finalising and reopening years.
  - `staff`: client work, including custom depreciation rates.
  - `viewer`: read-only.
- **Web:** React, Vite, TypeScript, TanStack Query, React Router, CSS modules. No UI kit in v1.

## Layout
```text
crates/core      pure domain: money, chart, ledger, mapping, depreciation, ReportDoc
crates/store     SQLite schema, migrations, repositories
crates/server    axum API, auth, command pipeline, sync feed; binary `acctd`
crates/import    bank statement parsers (OFX, QIF, per-bank CSV) and TB import
apps/web         React UI
packages/types   generated TS types (never hand-edited)
fixtures/        synthetic data only
docs/            domain.md (glossary and worked examples), decisions/ (ADRs)
tools/           local-only utilities (M8)
```

## Commands
- `make setup`: fetch Rust and pnpm dependencies, and install `cargo-insta`.
- `make dev`: server on :8080 and Vite on :5173 (Vite proxies `/api`).
- `make test`: cargo test and vitest.
- `make check`: fmt check, clippy with `-D warnings`, all tests, `tsc --noEmit`, and a check that generated types are up to date. It must pass before you call a task done.
- `make types`: regenerate the TypeScript types.
- `make db-reset`: wipe the dev database and load fixtures through the command pipeline.

## Working conventions
- Work directly on `master`; don't create branches. Commit each finished task there. The user saves and pushes with `zz_quicksave.txt` (stage all, commit, pull --rebase, push), so leave the tree in a state that is safe to commit as a whole.
- Propose a plan before changing more than about 5 files or any public type.
- Snapshots: `cargo insta review` is interactive, so don't use it. Read each pending `.snap.new` against its `.snap`. Run `cargo insta accept` only when you can explain every change, and say in the commit message why each one changed.
- When you add a dependency, explain why in the commit message.
- For accounting presentation questions (signs, grouping, wording, conventions), ask, then record the answer in `docs/domain.md`. Don't guess.
- Dates in the domain are `NaiveDate`; timestamps are UTC.

## Codespaces
- Forwarded ports stay private. Never make them public.
- The desktop shell and Windows builds aren't done here. Stay web-first until M7.
